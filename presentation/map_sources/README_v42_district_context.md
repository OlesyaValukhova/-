# Происхождение районного контекста v42

Дата получения: 17.11.2026 (UTC timestamp записывается в `district_boundaries_audit_v42.json`).

## Источник
Восемнадцать отношений OpenStreetMap, перечисленных в документации OSM Wiki для районов Санкт-Петербурга. Ожидаемые теги: `boundary=administrative`, `admin_level=5`. Сама документация OSM Wiki указывает, что информация для разметки границ берётся с официального сайта Санкт-Петербурга.

## Обработка
- Запрос Overpass API по фиксированному списку из 18 relation ID.
- Преобразование ответа в GeoJSON библиотекой `osm2geojson`.
- Проверка названий, тегов, типа и валидности геометрии.
- Перепроецирование EPSG:4326 → EPSG:32636.
- Проверка пространственного перекрытия с bbox 3 330 полигонов BlocksNet.
- Сохранение исходного ответа, GeoJSON и JSON-аудита.

## Использование
Тонкие линии административных границ накладываются поверх квартальной тематической карты только для ориентации. Ни один B1-показатель не пересчитывается по районам. Пространственная единица анализа и представления результатов остаётся кварталом BlocksNet.

## Особенность OSM-конвертации

В отношении Колпинского района и некоторых других районов присутствуют вложенные relation-члены с ролью `subarea`. Это ссылки на муниципальные/подчинённые территории, а не кольца границы родительского района. Для сборки геометрии из конвертационного входа исключаются только такие вложенные relation-ссылки; исходный Overpass JSON сохраняется без изменений, все внешние way-геометрии остаются. Число исключённых ссылок фиксируется в `district_boundaries_audit_v42.json`. Это не меняет контур родительского района и не затрагивает B1-данные.
