# Общегородской сбор Навигатора

Запуск проверен 09.11.2026: публичный `/api/program/list_odo/` без `district` сообщает 43 252 программы и возвращает страницы по 100 записей. Число относится к моменту запроса и может изменяться. Это весь каталог API, а не доказанная полнота рынка занятий Петербурга. В частности, карточка не обязательно означает действующую группу.

## Запуск

Из корня проекта в PowerShell с правами администратора:

```powershell
& '.\nir-digital-urbanism\src\collect_navigator_direct.ps1' -InterfaceIndex 14 -City -CollectDetails
```

`InterfaceIndex` должен соответствовать текущему физическому подключению, а не VPN. Скрипт читает его текущий шлюз и добавляет только временные IPv4-маршруты `/32` к разрешённым DNS-адресам Навигатора. Если такой маршрут уже существует, скрипт отказывается его менять. Созданные маршруты удаляются в `finally`; принудительное уничтожение процесса/выключение компьютера может помешать этому, поэтому после аварии следует проверить журнал и маршруты, а не добавлять новые вслепую. VPN целиком не отключается. Административные права нужны Windows для маршрута, не сайту.

Без необходимости изменения маршрута достаточно обычного Python:

```powershell
& 'C:\Users\olesy\PycharmProjects\JupyterProject2\.venv\Scripts\python.exe' -u nir-digital-urbanism/src/parse_navigator.py --url 'https://dopobr.petersburgedu.ru/api/program/list_odo/?limit=100&offset=0&ordering=rating_avg_desc&page=1' --direct-http --output nir-digital-urbanism/data/navigator/city-NEW --max-pages 1000 --delay 1 --timeout 20 --retries 1
```

`--direct-http` выключает HTTP-прокси Python, но не обходит системный TUN. Выходная директория каталога должна быть новой. Не изменять фильтры при продолжении одной цепочки страниц.

## Что сохраняется

- `data/navigator/direct-<timestamp>/routing.log` — маршрут и его удаление.
- `collector.log` — текущая страница, число записей и ошибка, если была.
- `catalogue/page-*.json` — исходные ответы отдельных страниц.
- `catalogue/pages.json` — контрольная точка после каждой страницы.
- `catalogue/programs.csv` и `manifest.json` — итог завершившегося/остановившегося запуска, в том числе частичного.
- `program-details/<id>-detail.json`, `selection.json`, `manifest.json`, `details.log` — подробные карточки и их происхождение. Они запрашиваются только после успешного завершения списка, если указан `-CollectDetails`.

При 100 записях на страницу полный список требует около 433 запросов; полные карточки — около 43 тысяч дополнительных запросов. Второй этап может занять много часов или дольше; точное время до получения скорости не обещается. Запросы последовательные с паузой минимум 1 секунду. После трёх последовательных неудач карточки останавливаются. Возраст/адрес не придумываются из названий организаций. Отдельные групповые API в этом этапе не собираются.

Проверка сохранённой диагностической выборки от 20.10: во всех 12 карточках/31 группе вложенные `groups` совпадают с отдельным ответом групп по ID и общим полям; отдельный ответ добавляет только `free_places_count`. Аудит с SHA256 исходников: `results/navigator-city-preparation-20261109/embedded-groups-audit.json`. Это позволяет не планировать второй запрос групп для каждой карточки ради возраста/дат. Совпадение на этой выборке не доказывает совпадения во всём новом каталоге; новая схема ещё требует проверки.

## Продолжение

Для частичного списка (новая директория создаётся автоматически маршрутизирующим скриптом):

```powershell
& '.\nir-digital-urbanism\src\collect_navigator_direct.ps1' -InterfaceIndex 14 -City -ResumePages 'ПОЛНЫЙ_ПУТЬ_К_ПРЕЖНЕМУ\catalogue\pages.json' -CollectDetails
```

Пустую выгрузку без единой страницы продолжать нельзя: нужно начать новый запуск. Для карточек повторяется команда с **тем же** источником `pages.json` и **тем же** каталогом карточек при работающем прямом доступе:

```powershell
& 'C:\Users\olesy\PycharmProjects\JupyterProject2\.venv\Scripts\python.exe' -u nir-digital-urbanism/src/collect_program_details.py --catalogue 'ПУТЬ\catalogue\pages.json' --output 'ПУТЬ\program-details' --delay 1 --timeout 20 --failure-stop 3
```

Уже сохранённые карточки проверяются по ID и пропускаются; чужая выборка/другой исходный файл в той же директории не допускаются. Предыдущие карточки и источники не перезаписываются при обновлении каталога: для нового среза нужна новая директория. На время отдельного продолжения карточек маршрут должен поддерживаться отдельно; повторный запуск общей команды создаёт новый запуск, а не подхватывает старые карточки автоматически.

## Когда можно говорить о полноте

Только после проверки цепочки `next`, неизменности фильтров и счётчика, уникальности ID и совпадения итогового числа со счётчиком API. `complete_unfiltered_api_catalogue=true` означает проверенный полный ответ данного API без содержательных фильтров. `complete_city_export` остаётся false: API не доказывает полноту всех поставщиков города. Полнота списка не означает полноту подробных карточек, адресов, возрастов, групп или вместимости.

Первый рабочий процесс этого запуска: elevated PowerShell PID 15412, папка `data/navigator/direct-20261109-145039`. PID исторический: перед мониторингом обязательно проверять, что процесс ещё существует и командная строка соответствует сборщику.

Список завершился в `data/navigator/direct-20261109-145039/catalogue`: 433 страницы, 43 253 уникальных ID, без повторов. Счётчик во время сбора вырос с 43 252 до 43 253. Автоматический переход был предусмотрен только при коде 0, поэтому массовые карточки запущены отдельно через новый параметр:

```powershell

```

Живой запуск при проверке: `data/navigator/direct-20261109-152247`, PowerShell PID 12064; новый монитор PID 6996, интервал 600 секунд. Эти PID не следует считать живыми без повторной проверки. Карточки сохраняются в `program-details`, журнал — `details.log`, статус монитора — `monitor-status.json`. Для продолжения тех же карточек параметр `-DetailsDirectory` позволяет указать прежнюю папку `program-details` с тем же исходным файлом; он не используется вместе с `-City`.

По просьбе исследователя запущен `monitor_navigator.py --run <папка запуска> --pid 15412 --interval 600 --hours 72`. Он каждые 10 минут читает прогресс и состояние процесса, пишет `monitor.jsonl` и `monitor-status.json`, предупреждает об отсутствии изменений более 20 минут и завершает наблюдение после остановки/завершения сборщика. Он не перезапускает сборщик, не меняет маршруты и не отправляет сообщения в чат. Число строк в его оперативном отчёте не является аудитом уникальности ID.

Для преобразования сохранённых карточек в отдельные таблицы программ и групп используется офлайн-команда:

```powershell
& 'C:\Users\olesy\PycharmProjects\JupyterProject2\.venv\Scripts\python.exe' nir-digital-urbanism/src/export_navigator_details.py --input 'ПУТЬ\program-details' --output 'НОВАЯ_ПАПКА_ТАБЛИЦ' --as-of 2026-11-09
```

Она сохраняет исходные возрастные поля, адрес, координаты, категории, групповые даты и статус, добавляет флаги качества и контрольные суммы. Не строит вымышленные площадки по адресу организации и не превращает лимиты групп в проверенную вместимость. Покрытие даты интервалом не подтверждает фактическую работу группы. Проба: 5 карточек и 23 группы в `results/navigator-city-preparation-20261109/card-probe-tables/`; это проверка обработки, не репрезентативная оценка города.
